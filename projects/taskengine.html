Task Flow Engine — 可設定的任務流程引擎

企業金融授信平台的規則引擎 + 圖形化流程編輯器 · Java/Spring · Vue 3 + GoJS + Electron

這是任職期間的團隊專案（3 人），原始碼屬公司所有、不公開。 本頁呈現架構設計與我實際負責的部分；文中不含任何真實業務規則與客戶資訊。

問題

批次或流程型的金融業務，需要對多筆資料依規則執行一連串條件檢核，並依結果分支、迴圈。 傳統做法把這些規則直接寫成程式碼 —— 規則一改就要改 code、測試、部署； 程式碼隨規則膨脹，邏輯散落各處難以追蹤。金融業的業務規則偏偏是變動最頻繁的東西。

設計：把流程邏輯資料化

業務檢核不落入 codebase：所有流程邏輯以設定方式存於資料庫， 引擎讀取設定、組合 Task/Block 執行 —— 規則調整變成資料維護，不再是程式變更。 搭配完整的 log 機制，每一步判斷都可回溯。

  • 三類任務自由組合：CONTROL（分支／FOR 迴圈／巢狀迴圈）、OPERATOR（表達式運算）、QUERY（自動資料查詢）
  • 表達式引擎：Shunting-yard 解析 + SpEL 求值，支援四則運算、日期加減、金融運算與自定義函數
  • 變數池：任務結果暫存為變數，供後續任務的邏輯判斷使用
  • 動態查詢：查詢規則同樣資料化，以 JPA Criteria API 動態組合條件

Flow Studio：給人用的編輯器

規則存在資料表裡，對維護的人是災難 —— 所以配套做了圖形化編輯器： 以 GoJS 呈現整條任務流程，直接在畫布上編輯節點屬性、調整分支， 匯出／匯入 JSON 與資料表對接，並以 Electron 打包成桌面應用發佈給團隊使用。

層技術
引擎Java · Spring Boot · 規則資料表 · 完整執行 log
編輯器Vue 3（Composition API）· TypeScript · Vite · GoJS · PrimeVue
桌面打包Electron Forge（Windows 發佈）
測試Playwright E2E · Vitest · JUnit

我負責的部分

  • LOG 執行路徑分析模組（Flow Studio）：上傳引擎執行 log，重建整條執行路徑並以表格呈現關鍵決策點；支援依業務模組快速預設分析欄位。規則資料化的架構能不能維運，就靠這一塊。
  • 流程編輯核心修正：迴圈區塊（ForBlock/SubBlock）內的任務接續候選範圍限縮、空區塊視為自然結束的流程收斂、匯出 JSON 的順序一致性校驗。
  • 引擎端：SpEL 金融運算函數、邏輯執行器測試、變數解析重構。
  • 發佈管理：版本打包（Electron）與發佈流程，並以 issue → AI 輔助修正 → review 的工作流迭代。

我學到的事

  • 彈性有價格：規則資料化換來不改 code 的彈性，也換來「設定即程式」的除錯難度 —— 所以 log 機制與視覺化工具不是加分項，是這個架構能活下來的必要條件。
  • 工具鏈完整才算交付：引擎、編輯器、log 分析、打包發佈，缺一角使用者就會回頭要求「還是寫死在 code 裡吧」。
